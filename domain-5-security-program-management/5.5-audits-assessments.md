# 5.5 - Audits and Assessments

**Official CompTIA SY0-701 objective:** 5.5 - Explain types and purposes of audits and assessments.
**Recommended resource:** Professor Messer SY0-701 - "Audits", "Penetration Testing" (Domain 5, Section 5.5)

---

## Audit Types

### Internal

| Type | Description |
|---|---|
| **Compliance audit** | Verify adherence to policies and regulations |
| **Audit committee** | Board-level oversight of the audit function |
| **Self-assessments** | Department-level evaluation against standards |

### External

| Type | Description |
|---|---|
| **Regulatory exam** | Imposed by the regulator (FDIC exam for banks, HIPAA OCR audit) |
| **Independent third-party** | External auditor - maximum credibility |
| **Assessment** | Less formal than an audit - advisory-style findings |

---

## Attestation

Formal written statement by the responsible party confirming that a control is in place.

**Example:** SOC 2 Type II - the auditor attests that controls operated effectively over the audit period.

| SOC 1 | SOC 2 |
|---|---|
| Controls related to financial statements | Controls for security, availability, integrity, confidentiality, privacy |
| Relevant to financial auditors | Relevant to customers evaluating a service provider |

| Type I | Type II |
|---|---|
| Controls in place at a point in time | Controls actually operating over a period (6-12 months) |
| Less robust | **More robust - preferred** |

## Penetration Testing

Authorized simulated attack to identify vulnerabilities before attackers do.

### Environment Types

| Type | Attacker knowledge | Scenario |
|---|---|---|
| **Unknown environment** (Black box) | None - simulates an external attacker | Most realistic external test |
| **Known environment** (White box) | Full access to docs, code, infrastructure | Most thorough - efficient for code review |
| **Partially known** (Gray box) | Some information | Compromise between the two |

### Pentest Types

| Type | Scope |
|---|---|
| **Physical** | Test physical security controls (tailgating, lock picking) |
| **Offensive** (Red team) | Traditional red team - attack and compromise |
| **Defensive** (Purple team) | Defensive team observes and improves detection |
| **Integrated** | Red + blue team together - maximizes learning |

### Reconnaissance

| Type | Description | Example | Detectability |
|---|---|---|---|
| **Passive** | No direct interaction with the target | OSINT, Shodan, WHOIS, LinkedIn, Google Dork | Undetectable |
| **Active** | Direct interaction with the target | Nmap scan, DNS zone transfer, service enumeration | May trigger IDS/IPS |

## Practice Questions

**Q: An organization asks a vendor to prove that its security controls have been operating effectively for 12 months. What document to request?**
Answer: **SOC 2 Type II** - attests that controls were in place and functioning over an extended period.

**Q: A pentester scans ports on a server using Nmap. Is this passive or active reconnaissance?**
Answer: **Active** - direct interaction with the target, potentially detectable by monitoring systems.

**Q: An auditor engages a pentest where the tester has full access to network diagrams, source code, and configurations. What type of test is this?**
Answer: **White box** (Known environment) - the most thorough because the tester can focus on exploitation rather than discovery.
