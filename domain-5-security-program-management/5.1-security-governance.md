# 5.1 - Security Governance

**Official CompTIA SY0-701 objective:** 5.1 - Summarize elements of effective security governance.
**Recommended resource:** Professor Messer SY0-701 - "Security Governance", "Policies and Procedures" (Domain 5, Section 5.1)

---

## Governance Framework

Governance defines *how* security decisions are made and *who* is responsible.

**Hierarchy:** Policy -> Standard -> Procedure -> Guideline

---

## Key Documents

| Document | Purpose | Nature |
|---|---|---|
| **Policy** | High-level statement of intent - *what must be done* | Mandatory |
| **Standard** | Specific mandatory requirements - *how the policy is implemented* | Mandatory |
| **Procedure** | Step-by-step instructions - *exactly how to perform a task* | Mandatory |
| **Guideline** | Recommended best practices (not mandatory) | Recommended |

> **Mnemonic:** Policy -> Standard -> Procedure -> Guideline. From most abstract to most concrete. The Guideline is the only non-mandatory document.

### Important Policy Types

| Policy | Coverage |
|---|---|
| **AUP** (Acceptable Use Policy) | Rules for using company systems and networks - what users are and are not allowed to do |
| **Information security policy** | Overall security requirements |
| **Business continuity policy** | Maintaining operations during a disruption |
| **Disaster recovery policy** | Restoring IT systems after a disaster |
| **Incident response policy** | Detection, response, and recovery from incidents |
| **SDLC policy** | Security requirements in software development |
| **Change management policy** | Process for approving and implementing changes |

---

## Standards

| Standard type | Concrete example |
|---|---|
| **Password** | Minimum 12 characters, complexity requirements, no reuse of last 10 |
| **Access control** | Mandatory RBAC; MFA for privileged access |
| **Physical security** | Badge required for server room; visitor escort required |
| **Encryption** | AES-256 at rest, TLS 1.2+ in transit |

---

## Procedures

Step-by-step operational processes:
- **Change management:** Specific steps to request, approve, and implement changes
- **Onboarding/offboarding:** Account provisioning/de-provisioning procedures
- **Playbooks:** IR procedures for specific scenarios (ransomware, phishing, insider threat)

---

## External Considerations

| Type | Examples |
|---|---|
| **Regulatory** | HIPAA (US healthcare), PCI DSS (payment cards), GDPR (EU), SOX (US finance) |
| **Legal** | Applicable law in jurisdictions of operation |
| **Industry** | NIST CSF, ISO 27001, CIS Controls |
| **Local/regional** | State laws (California CCPA), regional data residency |
| **National** | Federal laws (FISMA), national cybersecurity frameworks |
| **Global** | GDPR (EU), cross-border data transfer rules |

---

## Governance Structures

| Structure | Description |
|---|---|
| **Boards** | Executive oversight of risk and compliance |
| **Committees** | Cross-functional groups (security steering committee) |
| **Government entities** | Regulatory bodies, law enforcement |
| **Centralized** | Single authority - consistent but slow |
| **Decentralized** | Business unit autonomy - flexible but inconsistent |

---

## Roles and Responsibilities

| Role | Responsibility |
|---|---|
| **Data Owner** | Business responsibility for data - defines classification |
| **Data Controller** | Determines the purpose and means of processing (GDPR term) |
| **Data Processor** | Processes data on behalf of the controller (third party) |
| **Data Custodian/Steward** | Technical implementation of security controls for data |

---

## Practice Questions

**Q: A document that states "all passwords must be at least 12 characters and contain at least one uppercase letter" is what type of governance document?**
Answer: **Standard** - specific, mandatory, details how to implement the policy.

**Q: A document that states "users must not use company computing resources for personal purposes" is what type?**
Answer: **AUP (Acceptable Use Policy)** - a type of policy.

**Q: What is the difference between Data Owner and Data Custodian?**
Answer: The **Data Owner** is *business* responsible (decides classification and who has access). The **Data Custodian** is *technically* responsible (implements controls, manages backups, applies permissions decided by the Owner).
