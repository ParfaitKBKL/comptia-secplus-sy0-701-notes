# 2.5 - Mitigation Techniques for Enterprise Security

**Official CompTIA SY0-701 objective:** 2.5 - Explain the purpose of mitigation techniques used to secure the enterprise.
**Recommended resource:** Professor Messer SY0-701 - "Mitigation Techniques", "Hardening" (Domain 2, Section 2.5)

## Core Mitigation Strategies

| Technique | Purpose |
|---|---|
| **Segmentation** | Divide network into zones - limits lateral movement if a system is compromised |
| **Access control** | Enforce who can access what (ACL, RBAC, ABAC) |
| **Application allow list** | Only approved applications can execute - prevents unknown malware |
| **Isolation** | Quarantine compromised or untrusted systems |
| **Patching** | Remediate known vulnerabilities with vendor-supplied fixes |
| **Encryption** | Protect confidentiality of data at rest and in transit |
| **Monitoring** | Continuous visibility into activity (SIEM, EDR, NetFlow) |
| **Least privilege** | Users/processes get minimum rights to perform their function |
| **Configuration enforcement** | Baseline configs enforced via GPO, MDM, Ansible, Terraform |
| **Decommissioning** | Properly retire assets - remove access, sanitize data |

---

## Access Control

| Concept | Description |
|---|---|
| **ACL (Access Control List)** | Rules on network devices or filesystems defining permitted traffic/access |
| **Permissions** | Filesystem-level rights (read, write, execute) |
| **Principle of least privilege** | Grant only what is needed, nothing more - reduces blast radius |

## Hardening Techniques

Hardening = reducing the attack surface of a system.

| Technique | Details |
|---|---|
| **Encryption** | Encrypt disk, communications, sensitive files |
| **Endpoint protection** | AV/EDR installation and configuration |
| **Host-based firewall** | Local firewall rules (Windows Defender Firewall, iptables, nftables) |
| **HIPS** | Host-based Intrusion Prevention System - blocks suspicious behavior at endpoint level |
| **Disable ports/protocols** | Close unused ports (Telnet 23, FTP 21, SMBv1, RDP if not needed) |
| **Change default passwords** | Mandatory first step on any new device |
| **Remove unnecessary software** | Reduce attack surface - if it is not needed, remove it |
| **Disable unnecessary services** | Fewer active services = fewer attack vectors |

### Hardening Checklist (General)

```
1. Apply latest patches
2. Change all default credentials
3. Disable unnecessary services/ports
4. Enable host-based firewall
5. Install and configure endpoint protection (AV/EDR)
6. Enable audit logging
7. Enforce encryption (disk + transit)
8. Apply least privilege to all accounts
9. Remove unused accounts
10. Configure automatic updates
```

## Network Segmentation Strategies

```
Internet
    |
   [DMZ] <- Web servers, mail relays (public-facing)
    |
  [Firewall]
    |
[Internal Network]
    |-- [User VLAN]
    |-- [Server VLAN]
    |-- [IoT VLAN]         <- Isolated - less secure devices
    +-- [Management VLAN]  <- Highly restricted, jump server access only
```

- Each zone has its own firewall rules
- Zero-trust approach: no implicit trust between zones
- **Micro-segmentation:** host-level controls (not just VLAN-based)
- Goal: an attacker who compromises the IoT VLAN cannot reach the Server VLAN

## Application Allow Listing vs. Deny Listing

| Approach | Logic | Security Level |
|---|---|---|
| **Allow list** (whitelist) | Only listed applications run | High - blocks all unknown code, including zero-days |
| **Deny list** (blacklist) | Listed applications blocked, rest allowed | Low - misses unknown malware |

> Allow listing is the gold standard but has significant operational overhead (managing the list). Widely used in kiosk, industrial (ICS/SCADA), and high-security environments.

## MSP / MSSP - Security Providers

| Acronym | Role |
|---|---|
| **MSP** (Managed Service Provider) | Solution for organizations needing IT services without internal IT staff - manages infrastructure |
| **MSSP** (Managed Security Service Provider) | Third-party specialized in IT security management - managed SIEM, SOC-as-a-Service |
| **MSA** (Master Service Agreement) | Umbrella contract defining general terms between a client and a service provider |

## Product Lifecycle - Security Implications

| Phase | Definition | Security Impact |
|---|---|---|
| **EOS** (End of Sale) | Product no longer manufactured or sold (but still supported) | Plan migration |
| **EOL** (End of Life) | Product no longer manufactured, sold, or **supported** | **No patches possible** - permanent unmitigatable risk - isolate or replace |

> An EOL system with known CVEs and no available patch = risk that cannot be mitigated by patching. Mitigation requires network isolation, compensating controls, or replacement.

## Email Security

| Tool | Role |
|---|---|
| **Email security gateway** | Deployed inline (on-prem or cloud), real-time protection against spam, phishing, and malware in emails. Analyzes traffic before it reaches inboxes. |
| **SPF** | Sender Policy Framework - verifies the email came from an authorized server for the domain |
| **DKIM** | DomainKeys Identified Mail - cryptographic signature on the email to verify authenticity |
| **DMARC** | Policy based on SPF+DKIM - defines what to do if an email fails verification |

## Practice Questions

**Q: An organization uses an approach where only applications on an approved list can run on endpoints. What technique is this?**
Answer: **Application allow listing** - blocks all code not explicitly approved.

**Q: A critical legacy system cannot be patched because the vendor reached EOL. What is the BEST mitigation without immediate replacement?**
Answer: **Network segmentation/isolation** (compensating control) plus enhanced monitoring.

**Q: Which hardening technique provides the BEST protection against zero-day attacks on endpoints?**
Answer: **EDR (Endpoint Detection and Response)** with behavioral analysis combined with **application allow listing** - together they offer the best protection without relying on signatures.
