## Infrastructure Considerations

### Device Placement
- **Firewalls** at the perimeter and between internal zones
- **IDS/IPS:** inline (IPS, blocks) or out-of-band (IDS, alerts only) depending on performance requirements
- **Jump servers** in the management zone - only way to reach sensitive assets
- **Sensors/TAPs:** receive a copy of traffic (no impact on flow)

### Security Zones

```
Internet -> [Perimeter FW] -> DMZ -> [Internal FW] -> LAN
                                             |
                                     Management Zone (most restricted)
```

| Zone | Contents | Trust Level |
|---|---|---|
| Internet | External | Untrusted |
| DMZ | Web servers, mail relays, reverse proxy | Low |
| LAN | Workstations, printers | Medium |
| Server zone | Application servers, databases | High |
| Management zone | Hypervisors, switches, routers | Maximum - jump server access only |

### Attack Surface
Reduce by: removing unused services, closing ports, disabling obsolete protocols, decommissioning legacy systems.

### Failure Modes

| Mode | Behavior | Priority | Use Case |
|---|---|---|---|
| **Fail-open** | On failure, traffic is allowed | Availability | Life-safety systems (fire doors, medical emergencies) |
| **Fail-closed** | On failure, traffic is blocked | Security | Most security devices |

> Most security devices should be configured **fail-closed**. An IPS configured fail-open means that if it crashes, all traffic passes uninspected.

### Device Attributes

| Attribute | Description | Example |
|---|---|---|
| **Active** | Actively blocks/modifies traffic | IPS, firewall |
| **Passive** | Monitors only | IDS, tap/span port |
| **Inline** | Device sits in the traffic path | Inline IPS, firewall |
| **Tap/Monitor** | Receives a copy of traffic | Passive IDS, packet analyzer |

## Network Appliances

| Appliance | Function |
|---|---|
| **Jump server** (Bastion host) | Single, hardened access point into restricted network segments - all administration goes through it |
| **Proxy server** | Intermediary between clients and internet - caching, filtering, inspection, anonymization |
| **IPS** | Inline; actively blocks malicious traffic based on signatures/behavior |
| **IDS** | Out-of-band; detects and alerts on threats - does not block |
| **Load balancer** | Distributes traffic across servers - also provides DDoS mitigation and high availability |
| **Sensor** | Collects network data for analysis (NetFlow, packet capture) |
| **UTM** (Unified Threat Management) | All-in-one: firewall + URL filtering + content inspection + AV gateway + IDS/IPS + email protection. Often a physical appliance. |

## Port Security

### 802.1X - Network Access Control (NAC)

Network authentication standard - authenticates devices **before** granting network access.

**Components:**
| Role | Description |
|---|---|
| **Supplicant** | Device requesting access (PC, phone) |
| **Authenticator** | The switch or Wi-Fi access point |
| **Authentication Server** | RADIUS server (Remote Authentication Dial-In User Service) |

### EAP (Extensible Authentication Protocol)

Framework used with 802.1X. Variants:

| Variant | Method | Security |
|---|---|---|
| **EAP-TLS** | Certificate-based (client + server) | Most secure - requires a PKI |
| **PEAP** | Password in a TLS tunnel | Good security, easier to deploy |
| **EAP-TTLS** | Username/password in a TLS tunnel | Good security, flexible |

## Firewall Types

| Type | OSI Layer | Key Feature |
|---|---|---|
| **Packet filter** | Layer 3-4 | IP/port based rules - stateless, fast |
| **Stateful** | Layer 4 | Tracks connection state - smarter than packet filter |
| **WAF** (Web Application Firewall) | Layer 7 | HTTP/HTTPS inspection, blocks SQLi/XSS/OWASP Top 10 |
| **UTM** | Multiple | All-in-one: FW + IPS + AV + VPN + content filtering |
| **NGFW** (Next-Generation Firewall) | Layer 7 | Deep packet inspection, application awareness, identity-based rules |

> NGFW vs. UTM: both do deep inspection, but NGFW is typically enterprise-grade performance-oriented, UTM is often for SMBs.

## Secure Communications

| Technology | Use Case |
|---|---|
| **VPN** | Encrypted tunnel over an untrusted network (site-to-site or remote access) |
| **TLS** | Transport encryption for most protocols (HTTPS, IMAPS, etc.) |
| **IPSec** | Network-layer encryption - used in site-to-site VPNs |
| **SD-WAN** | Software-defined WAN - centralizes routing/security policy across branches |
| **SASE** | Combines SD-WAN + cloud-delivered security (CASB, SWG, ZTNA) - edge security |

### IPSec Components

| Component | Role |
|---|---|
| **AH** (Authentication Header) | Integrity + authentication, **no encryption** |
| **ESP** (Encapsulating Security Payload) | Integrity + authentication + **encryption** - most commonly used |
| **IKE** (Internet Key Exchange) | Key exchange for IPSec |
| **Tunnel mode** | Entire packet encrypted (site-to-site) |
| **Transport mode** | Only the payload encrypted (host-to-host) |

> **ESP is preferred over AH** because ESP encrypts data in addition to authenticating it. AH alone provides no confidentiality.

## Practice Questions

**Q: An IPS is configured to pass traffic through if its CPU exceeds 90% utilization. What failure mode is configured and what is the risk?**
Answer: **Fail-open** - if the IPS is overloaded, all traffic passes uninspected. Risk: a DDoS attack can saturate the IPS to bypass detection.

**Q: Which IPSec component provides BOTH authentication AND data confidentiality?**
Answer: **ESP** (Encapsulating Security Payload).

**Q: An administrator wants only approved company devices to connect to the corporate Wi-Fi. What is the BEST technology to use?**
Answer: **802.1X with EAP-TLS** (certificate-based authentication) - the certificate proves the device is managed by the company.
