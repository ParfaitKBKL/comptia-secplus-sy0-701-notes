# 3.3 - Data Protection Concepts and Strategies

**Official CompTIA SY0-701 objective:** 3.3 - Compare and contrast concepts and strategies to protect data.
**Recommended resource:** Professor Messer SY0-701 - "Data Classifications", "Data Protection" (Domain 3, Section 3.3)

---

## Data Types

| Type | Examples |
|---|---|
| **Regulated** | PII, PHI, financial data subject to GDPR, HIPAA, PCI DSS |
| **Trade secret** | Proprietary formulas, source code, business processes - protected by commercial law |
| **Intellectual property** | Patents, trademarks, copyrights |
| **Legal information** | Attorney-client communications, litigation documents |
| **Financial information** | Revenue data, forecasts, banking records |
| **Human-readable** | Documents, reports, emails |
| **Non-human-readable** | Binary files, encrypted data, database blobs |

---

## Data Classifications

Most organizations use a 4-tier system:

| Level | Description | Example |
|---|---|---|
| **Public** | No harm if disclosed | Marketing materials, press releases |
| **Private / Internal** | Not for external sharing | Internal policies, org charts, procedures |
| **Sensitive / Confidential** | Limited distribution, business impact if leaked | Customer data, financial projections, contracts |
| **Restricted / Critical** | Severe harm if disclosed; need-to-know only | Encryption keys, M&A plans, highly sensitive PII |

> **Data classification drives security controls:** storage, transmission, destruction, and access. An unclassified asset cannot be properly protected.

---

## Data States

| State | Description | Primary Protection |
|---|---|---|
| **Data at rest** | Stored on disk, database, backup | Encryption (AES-256), access controls |
| **Data in transit** | Moving across the network | TLS, IPSec, VPN |
| **Data in use** | Actively processed in memory | Secure enclave, memory protection, confidential computing |

> **Data in use** is the hardest to protect - data must be decrypted to be processed. Emerging solutions: Intel SGX (Secure Guard Extensions), AMD SEV.

---

## General Data Considerations

| Concept | Definition |
|---|---|
| **Data sovereignty** | Data is subject to the laws of the country where it is physically stored - critical for multi-region cloud deployments |
| **Geolocation** | Where data physically resides affects legal jurisdiction and compliance requirements |
| **Data retention** | How long data must be kept (legal compliance vs. GDPR data minimization) |
| **Data minimization** | Only collect data that is strictly necessary - GDPR principle |

---

## Methods to Secure Data

| Method | How it works | Use case |
|---|---|---|
| **Geographic restrictions** | Restrict data to specific regions | Compliance with data residency laws |
| **Encryption** | Render unreadable without key | At rest, in transit, in use |
| **Hashing** | Verify integrity without storing original | Password storage, file integrity |
| **Masking** | Partially obscure data | Display `****-****-****-1234` |
| **Tokenization** | Replace sensitive data with a non-sensitive token | PCI DSS - store token, not the CC number |
| **Obfuscation** | Make data harder to understand | Code obfuscation, steganography |
| **Segmentation** | Separate sensitive data into isolated zones | Reduce blast radius |
| **Permission restrictions** | Enforce least privilege on data access | RBAC, DAC, MAC |
| **DLP** (Data Loss Prevention) | Detect/block unauthorized data movement | Prevent exfiltration, compliance |

### Tokenization vs. Encryption

| | Tokenization | Encryption |
|---|---|---|
| Reversible | Via the token vault | Via the encryption key |
| Original data stored | Separately in a secure vault | No - transformed to ciphertext |
| Key required | No | Yes |
| PCI DSS use | Yes - store token, not CC number | Yes |
| If compromised | Token useless without vault | Data recoverable if key is stolen |

## DLP - Data Loss Prevention

Technology that monitors and controls data movement to prevent leaks.

| Type | Protection |
|---|---|
| **Network DLP** | Inspects outbound network traffic (email, web uploads) |
| **Endpoint DLP** | Monitors actions on the endpoint (USB copy, printing, email) |
| **Cloud DLP** | Monitors data in cloud applications (Google Drive, OneDrive) |
| **Storage DLP** | Discovery and classification of stored sensitive data |

**Common triggers:** credit card numbers, social security numbers, keywords (confidential, secret), regex patterns.

## Practice Questions

**Q: A company replaces credit card numbers in its database with random identifiers. The real values are stored in a separate secure system. What technique is used?**
Answer: **Tokenization** - the token replaces the real value stored in a separate vault.

**Q: An employee sends an email containing a social security number to an external address. What solution would have prevented this?**
Answer: **DLP (Data Loss Prevention)** - detects sensitive patterns in outbound emails and can block or alert.

**Q: What concept means that data stored in a datacenter in Germany is subject to German law?**
Answer: **Data sovereignty**.
