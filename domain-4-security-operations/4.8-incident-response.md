# 4.8 - Incident Response

**Official CompTIA SY0-701 objective:** 4.8 - Given a scenario, perform incident response activities.
**Recommended resource:** Professor Messer SY0-701 - "Incident Response Process", "Digital Forensics", "Threat Hunting" (Domain 4, Section 4.8)

---

## IR Process - PDACERL

| Phase | Key activities |
|---|---|
| **Preparation** | Policies, playbooks, tools, training, tabletop exercises - everything prepared BEFORE the incident |
| **Detection** | SIEM alerts, user reports, threat hunting, vulnerability scan, monitoring|
| **Analysis**|                |
| **Containment** | Isolate affected systems - prevent propagation, lateral movement |
| **Eradication** | Remove malware, close the attack vector, remediate the vulnerability |
| **Recovery** | Restore systems, verify clean state, monitor closely |
| **Lessons Learned** | Post-incident review - what worked, what did not, improve |

> The NIST framework uses: Preparation -> Detection and Analysis -> Containment, Eradication and Recovery -> Post-Incident Activity
> PICERL is a popular exam mnemonic.

---

## Containment Strategies

| Strategy | Description |
|---|---|
| **Short-term** | Isolate the host (network quarantine, EDR isolation) - stops propagation immediately |
| **Long-term** | Rebuild or restore from a clean backup |

**Key decision:** Isolate now (lose live activity evidence) vs. monitor briefly (gather intelligence but risk propagation).

| Test | Description |

| **Simulation** | Full exercise - teams execute response procedures against a simulated scenario |

## Root Cause Analysis (RCA)

After eradication, determine:
- What was the initial access vector?
- What vulnerability was exploited?
- What compensating controls failed?
- What changes prevent recurrence?

---

## Threat Hunting

Proactive search for threats that have evaded existing controls.

| Type | Description |
|---|---|
| **Hypothesis-driven** | "What if an attacker is using LOLBins for lateral movement?" |
| **Intelligence-driven** | Hunt based on threat intel TTPs (MITRE ATT&CK) |

> Threat hunting **assumes compromise** - not reactive. It starts from the premise that an attacker is already present and searches for evidence.

## Digital Forensics

| Concept | Description |
|---|---|
| **Legal hold** | Preserve evidence before deletion or modification - triggered by legal proceedings |
| **Chain of custody** | Document every person who handled the evidence - essential for legal admissibility |
| **Acquisition** | Collect evidence in a forensically sound manner (write blockers, verification hashing) |
| **Preservation** | Maintain evidence integrity - never modify the original |
| **Reporting** | Document findings in a legally admissible format |
| **E-discovery** | Collection of electronic evidence for legal proceedings |

### Order of Volatility (evidence collection priority)

Collect the most volatile evidence first (disappears fastest):

| Order | Source | Volatility |
|---|---|---|
| 1 | CPU registers and cache | Highest |
| 2 | RAM (live memory) | Very high |
| 3 | Active network connections | High |
| 4 | Running processes | High |
| 5 | Disk contents | Low |
| 6 | Logs and backups | Lowest |

> **Collect the most volatile evidence first** before it is lost. A system reboot erases the first 4 levels.

## Key IR Metrics

| Metric | Definition |
|---|---|
| **MTTD** (Mean Time to Detect) | How long before the compromise is detected? |
| **MTTR** (Mean Time to Respond/Recover) | How long to restore normal operations? |

## Practice Questions

**Q: During a forensic investigation, an analyst wants to capture the RAM of an infected system. What essential precaution must be taken BEFORE copying the RAM?**
Answer: **Hash the RAM first** (before starting the capture) to prove its integrity, and use a **write blocker** to ensure evidence is not modified.

**Q: An organization discovers an active compromise. The IR team immediately isolates the system. What is the risk of this quick action?**
Answer: **Loss of volatile evidence** (active network connections, malicious processes in memory) - the attacker may still have had an active session that would have identified the C2 vector.

**Q: After an incident response, the team meets to analyze what happened, what worked, and what needs improvement. What phase of the IR cycle is this?**
Answer: **Lessons Learned** (or Post-Incident Review) - the last phase of PICERL.
