## Log Sources

| Source | What it shows |
|---|---|
| **Firewall logs** | Allowed/denied connections, IP addresses, ports, protocols |
| **Application logs** | User actions, errors, transactions in specific apps |
| **Endpoint logs** | Process creation, file access, registry changes, auth events |
| **OS security logs** | Windows Event Log (Security, System, Application channels) |
| **IPS/IDS logs** | Detected attack signatures, blocked traffic |
| **Network logs** | Connection metadata, DNS queries |
| **Metadata** | File metadata (creation date, author), email headers |
| **Proxy logs** | URLs accessed, web content, user agent strings |
| **Authentication logs** | Successful/failed login attempts, SSO, VPN access |

## Key Windows Event IDs (Blue Team reference)

| Event ID | Description | Relevance |
|---|---|---|
| **4624** | Successful logon | Normal baseline, monitor for unusual times/locations |
| **4625** | Failed logon | Brute force / password spray |
| **4648** | Logon with explicit credentials | Pass-the-Hash indicator |
| **4688** | Process creation | Malware execution, LOLBins |
| **4698** | Scheduled task created | Common persistence technique |
| **4720** | User account created | Backdoor creation |
| **4732** | User added to security group | Privilege escalation |
| **7045** | New service installed | Persistence technique, rootkit |

## Investigation Data Sources

| Source | Use case |
|---|---|
| **Vulnerability scans** | Identify what was exposed at the time of the incident |
| **Automated reports** | Scheduled SIEM reports - historical context |
| **Dashboards** | Real-time overview during an active incident |
| **Packet captures (PCAP)** | Complete network evidence - decode exact traffic |
| **Threat intel feeds** | Correlate IOCs with known threats (MITRE ATT&CK, VirusTotal) |
| **EDR telemetry** | Process tree, files created, network connections from the endpoint |

---

## NetFlow vs. Full Packet Capture

| | NetFlow | PCAP (Full Packet Capture) |
|---|---|---|
| Data captured | Metadata only (who, when, how much) | Full payload |
| Storage | Minimal | Very large |
| Privacy | No content inspection | Contains payload data |
| Use case | Baseline, anomaly detection, traffic analysis | Forensic reconstruction, protocol decoding |

> **Combined strategy:** NetFlow for continuous monitoring (storage-efficient), PCAP for targeted investigations triggered by alerts.

---

## Log Correlation Strategy

During an incident investigation, correlate in this order:

```
1. Firewall logs    -> Was an external connection established?
2. DNS logs         -> Was a suspicious domain resolved?
3. Endpoint logs    -> Was a process launched after the connection?
4. Auth logs        -> Was there lateral movement via compromised credentials?
5. DLP/email logs   -> Was there a data exfiltration attempt?
```

> **SIEM timeline correlation is essential.** Normalize timestamps to UTC - log sources in different time zones cause false sequencing.

## Practice Questions

**Q: An analyst wants to determine if a user accessed sensitive files on a server during a specific period. What log source to check first?**
Answer: **File server application logs** + **Windows Security Event Log (4663 - object access)** on the server.

**Q: What is the main limitation of NetFlow for forensic investigations?**
Answer: NetFlow captures only **metadata** - it shows that a connection occurred, the volume transferred, and the ports, but not **the content** of the exchanged data. To reconstruct an attack, a packet capture (PCAP) is required.

**Q: An administrator notices that Event ID 7045 was created on a server at 2am on a Saturday. What does this event mean?**
Answer: **A new service was installed** - a common persistence technique used by malware and attackers to maintain access after a reboot.
