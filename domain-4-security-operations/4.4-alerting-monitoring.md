# 4.4 - Security Alerting and Monitoring

**Official CompTIA SY0-701 objective:** 4.4 - Explain security alerting and monitoring concepts and tools.

## What to Monitor

| Level | Key elements |
|---|---|
| **Systems** | OS events, process creation, authentications, configuration changes |
| **Applications** | Error logs, access logs, transaction logs |
| **Infrastructure** | Network traffic, equipment health, configuration changes |
| **Identities** | Login attempts, resource access, permission changes |

---

## Key Monitoring Activities

| Activity | Description |
|---|---|
| **Log aggregation** | Centralize logs from all sources into the SIEM |
| **Alerting** | Trigger notifications on defined conditions |
| **Scanning** | Periodic vulnerability or compliance scans |
| **Reporting** | Dashboards and scheduled reports for stakeholders |
| **Archiving** | Long-term log storage for forensics and compliance |
| **Alert tuning** | Reduce false positives, improve signal-to-noise ratio |
| **Quarantine** | Isolate a suspicious system pending investigation |

---

## Main Tools

| Tool | Function |
|---|---|
| **SIEM** | Aggregates and correlates logs; generates alerts |
| **SCAP** | Security Content Automation Protocol - standardized vulnerability and compliance checking (CVE, CVSS, OVAL, XCCDF) |
| **CIS Benchmarks / DISA STIG** | Configuration compliance checks |
| **Agents vs. Agentless** | Agent = richer data; Agentless = simpler deployment |
| **Antivirus** | Signature + heuristic detection on endpoint |
| **DLP** | Data Loss Prevention - detects/blocks unauthorized data movement |
| **SNMP traps** | Network device alerts sent to a management station |
| **NetFlow** | Network traffic metadata (who talked to whom, how much data) |
| **Vulnerability scanners** | Nessus, OpenVAS, Qualys - CVE identification |
| **EDR** | Endpoint Detection and Response - behavioral monitoring, forensic capability |

---

## SIEM - Key Concepts

A SIEM (Security Information and Event Management) provides:

| Capability | Description |
|---|---|
| **Log aggregation** | Collection from heterogeneous sources (Windows, Linux, network, cloud) |
| **Normalization** | Common format for different log types |
| **Correlation** | Link related events across different sources (login + process + network) |
| **Alerting** | Rule-based and anomaly detection |
| **Retention** | Long-term storage for forensics |

### SIEM vs. SOAR

| | SIEM | SOAR |
|---|---|---|
| Primary function | Detection, alerting | Automated response |
| Human in the loop | Yes (analyst reviews alerts) | Reduces need for manual action |
| Integration | Log sources | SIEM + ticketing + response tools |
| Examples | Splunk, Microsoft Sentinel, IBM QRadar | Splunk SOAR, Palo Alto XSOAR, Swimlane |

## Alert Response Flow

```
Alert fires
    |
Triage (False Positive or True Positive?)
    |
Investigation (gather evidence, correlate)
    |
Containment (isolate suspicious system)
    |
Remediation (fix root cause)
    |
Closure and documentation
```

- **Alert tuning is continuous** - new false positives identified during investigation lead to a refined rule and less noise next time
- Document all tuning decisions to maintain an audit trail

## Practice Questions

**Q: What is the main difference between a SIEM and a SOAR?**
Answer: The **SIEM** aggregates, correlates, and generates alerts. The **SOAR** **automates the response** to alerts via playbooks - it can isolate a host, block an IP, create a ticket, all without human intervention.

**Q: An analyst receives 500 alerts per day, 480 of which are false positives. What is the priority action to take?**
Answer: **Alert tuning** - refine the rules to reduce false positives and improve the signal-to-noise ratio.

**Q: Does NetFlow capture the content of data transferred between two hosts?**
Answer: **No** - NetFlow captures only **metadata** (source, destination, port, volume, duration). For content, a **packet capture (PCAP)** is required.
