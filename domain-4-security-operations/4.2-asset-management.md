# 4.2 - Hardware, Software, and Data Asset Management

**Official CompTIA SY0-701 objective:** 4.2 - Explain the security implications of proper hardware, software, and data asset management.
**Recommended resource:** Professor Messer SY0-701 - "Asset Management" (Domain 4, Section 4.2)

---

## Asset Lifecycle

```
Acquisition -> Assignment/Accounting -> Monitoring/Tracking -> Decommissioning/Destruction
```

---

## Acquisition / Procurement

- Verify vendor security posture before purchase
- Control supply chain integrity (hardware tampering risk)
- Evaluate software for known vulnerabilities before deployment
- Require certifications (SOC 2, ISO 27001, FedRAMP for cloud)

---

## Assignment / Accounting

| Concept | Description |
|---|---|
| **Ownership** | Every asset has a named owner responsible for its security |
| **Classification** | Asset tagged according to data classification - drives handling requirements |

---

## Monitoring / Asset Tracking

| Method | Description |
|---|---|
| **Inventory** | Comprehensive list of all hardware and software assets |
| **Enumeration** | Active discovery of assets on the network (Nmap, CMDB, scanners) |
| **CMDB** | Configuration Management Database - centralized repository of assets and their relationships |

> **Fundamental rule:** You cannot protect what you do not know exists. Shadow IT creates unmanaged assets outside security control.

**Asset tracking tools:** CMDB, SIEM inventory, network scanners, deployment agents (SCCM, Jamf).

---

## Decommissioning / Destruction

This phase is critical - improperly decommissioned assets cause data leaks.

| Step | Description |
|---|---|
| **Sanitization** | Remove all data - overwrite, degauss, or cryptographic erase |
| **Destruction** | Physical destruction when sanitization is insufficient or impossible |
| **Certification** | Document the disposal process - chain of custody |
| **Data retention** | Before disposal, ensure legal retention requirements are met |

### Sanitization Methods

| Method | Media | Notes |
|---|---|---|
| **Overwriting** (DoD 5220.22-M) | Magnetic HDD | Multiple overwrite passes - minimum 3 recommended |
| **Degaussing** | Magnetic media (HDD, tapes) | Destroys data with a magnetic field - renders the drive unusable |
| **Cryptographic erase** | SSD/NVMe | Destroy the encryption key - data becomes unrecoverable |
| **Physical destruction** | Any media | Shredding, incineration - maximum assurance |

> **For SSDs, overwriting is unreliable** due to wear leveling (cells are not written linearly). Use **cryptographic erase** or physical destruction for SSDs.

---

## Software License Management

- Regular license audits to detect unauthorized software
- Remove unlicensed or unused software (attack surface reduction)
- **SAM** (Software Asset Management) - license management tool

---

## Practice Questions

**Q: An IT admin must ensure that data on a replaced SSD cannot be recovered before recycling it. What is the most appropriate method?**
Answer: **Cryptographic erase** (or physical destruction) - multi-pass overwriting is unreliable on SSDs.

**Q: An organization is replacing its servers. It must document who took possession of each hard drive to ensure none disappear. What concept is being applied?**
Answer: **Chain of custody** during decommissioning.

**Q: A network scanner detects 350 devices on the network but the CMDB only lists 300. What is the problem and the risk?**
Answer: **Shadow IT / unmanaged assets** - the 50 untracked devices likely receive no patches, no monitoring, and no security controls.
